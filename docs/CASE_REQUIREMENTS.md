# Требования кейса и проверенные данные

Основание: README выданного набора, описание «HackAlem AI — Граф денег» и starter. Требования ниже отделены от измеренных результатов.

## Обязательный результат

- Одна команда: три Parquet → показатели → роли и группы → три заполненных CSV. Основной расчёт работает локально без обязательного LLM, GPU или облачного кластера.
- Каждому счёту, включая изолированный, назначены роль, сила правила, группа, приоритет и непустое численное основание.
- Шесть ролей: `consolidator`, `transit`, `distributor`, `terminal`, `coordinator`, `peripheral`. Правила приведены в [README.md](../README.md).
- Для группы показаны размер, seed, внутренний оборот, ведущие GID и гипотеза.
- По официальному набору сформировано не менее 20 кандидатов с причинами. Реализация выдаёт top-50 без известных seed.
- Интерфейс позволяет найти GID, просмотреть направленные связи и объяснить роль по операциям. Для защиты нужны живой прогон и разбор двух–трёх счетов.

## Контракт CSV

| Файл | Обязательные поля |
|---|---|
| `nodes_roles.csv` | `gid,role,role_score,cluster_id,priority_score,evidence` |
| `clusters.csv` | `cluster_id,n_nodes,n_seed,sum_kzt_internal,top_gids,hypothesis` |
| `top_nodes.csv` | `rank,gid,role,priority_score,why` |

Для официального набора в `nodes_roles.csv` ровно 2 248 строк. `role_score` и `priority_score` — от 0 до 1; `evidence` непустое, содержит числа и занимает не более 200 символов. Дополнительные колонки допустимы.

Исходный GID имеет тип int64. API передаёт его строкой, чтобы JavaScript не округлял большие значения; CSV содержит полную десятичную запись. Для произвольных пользовательских идентификаторов читайте CSV со строковым типом GID, чтобы сохранить ведущие нули.

## Проверенный набор

| Таблица | Строк | Основные поля |
|---|---:|---|
| `nodes.parquet` | 2 248 | `gid,depth,is_seed` |
| `edges.parquet` | 3 119 | `src,dst,sum_kzt,n_tx,depth` |
| `transactions.parquet` | 4 840 | `src,dst,date,sum_kzt` |

- Период: 1–31 июля 2026; валюта KZT; оборот **365 890 012,01 ₸**.
- 81 seed; обход по исходящим связям до четырёх переходов.
- 19 изолированных узлов сохранены в графе и выгрузках.
- 444 узла четвёртого перехода не имеют наблюдаемых исходящих.
- Полный граф содержит 35 слабосвязных компонент, включая 19 изолятов.
- Точность времени — день. Исходных банковских transaction ID нет; `tx-...` — технические номера строк приложения.

Загрузчик сверяет пары, суммы и количество операций между edges и transactions. Одинаковые строки сохраняются как отдельные операции. Полученные **66 групп Louvain** не являются эталонной разметкой.

## Ограничения наблюдения

Выгрузка не показывает полный баланс. Входящие seed из-за границ выборки неизвестны; исходящие за четвёртым переходом обрезаны. Согласно условиям кейса, операции ниже 5 000 ₸ и внешние переводы не входят в наблюдение.

Нельзя устанавливать порядок операций внутри дня или скорость за 60 минут. Минутные показатели отключены; дневное совпадение входа и выхода не связывает конкретные суммы.

Нет сведений о владельцах, остатках, назначении платежей и размеченных ролях. Эвристики и Isolation Forest помогают выбрать порядок проверки, но не доказывают нарушение и не дают калиброванную вероятность.

## Воспроизводимость

```sh
python pipeline.py --data data/official --out out
python -m pytest tests -q
```

Измеренный локальный прогон: **2,34–2,45 с**, 2 248 строк ролей, 66 групп, 50 кандидатов. Полный набор тестов: **100 passed**, одно `StarletteDeprecationWarning`, **11,67 с**. Это измерение текущей среды, а не гарантия времени на любом компьютере.

Официальные файлы находятся локально в `data/official` и не публикуются в Git. Репозиторий содержит учебный набор и самостоятельные тестовые примеры. Проверки с официальными файлами могут пропускаться при их отсутствии; основные регрессионные тесты используют создаваемые примеры.

MVP ограничен 5 000 узлами. Для миллиона узлов потребуется отдельное хранение, пакетные и приближённые расчёты и выдача подграфов. Такая нагрузка не проверялась.
