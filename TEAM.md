# Работа втроём без параллельных версий сайта

## Одно решение, три зоны ответственности

| Участник | Зона | Файлы / результат |
| --- | --- | --- |
| Владелец интерфейса | Единственный основной сайт и перенос согласованного дизайна | `app.py`, `.streamlit/` либо frontend сокомандника |
| Владелец аналитики | Признаки, роли, рейтинг, контракт данных | `pipeline.py`, тесты аналитики, три CSV |
| Интегратор / демо | Проверка сценариев, README, презентация, слияния | `README.md`, тестовый чек-лист, финальная сборка |

Перед работой подтвердите в командном чате, **какой MVP является основным**. Не разрабатывайте два интерфейса независимо. Ветка `design/moneymap-workspace` — изолированное предложение дизайна для существующего Streamlit; если основной сайт на другом стеке, переносите макет и токены, а не весь `app.py`.

## Правила Git

1. Каждый работает в своей ветке: `ui/...`, `analysis/...`, `docs/...`.
2. Перед началом: `git fetch origin`, затем новая ветка от актуального `origin/main`.
3. За каждым файлом один владелец на время задачи. Ветка сама по себе не предотвращает конфликты при редактировании одинаковых строк.
4. Небольшой проверяемый коммит → push своей ветки → интегратор проверяет diff и сливает.
5. Не делать `push --force` в общие ветки и не перезаписывать чужие изменения.
6. Если возник конфликт, владелец файла и интегратор сравнивают обе версии. Не выбирать вслепую `ours` / `theirs`.
7. Ключи, `.env`, реальные данные и `.venv` не коммитить.

## Быстрая передача между участниками

Пишите: **ветка → коммит → изменённые файлы → команда проверки → что требуется от следующего участника**.

Контракт текущей аналитики: `out/nodes_roles.csv`, `out/clusters.csv`, `out/top_nodes.csv`. Идентификаторы gid во frontend передавать строками: 18-значные значения превышают точность JavaScript Number.

## Состояние двух кандидатов

Проверено по Git 23 сентября 2026:

- `main`, коммит `4a2df53`: корневой MoneyMap на Streamlit, расчёт по предоставленным parquet (2 248 узлов), три CSV по кейсу.
- `experiment/moneygraph-ai-mvp`, коммит `9ba1bb8`: React/FastAPI-кандидат в `alternatives/moneygraph-ai/`; согласно его README, стартует на 42 синтетических account, имеет загрузку CSV и лимит 1 500 узлов. Проверка этого кандидата в рамках дизайн-ветки — чтение исходников и README, не независимый запуск.
- `design/moneymap-workspace`: новый дизайн корневого Streamlit, `ui.css`, визуальный референс и тесты. `pipeline.py` не изменён.

Файлового пересечения с экспериментальной веткой сейчас нет, но **слияние не подключит два продукта друг к другу**. Для выбора React основным нужно назначить одного владельца интеграции, подключить проверенные исходные parquet/результаты pipeline к API, сохранить всех узлов (включая узлы без переводов), `is_seed` и глубину, обеспечить три требуемых CSV. Одной конвертации transactions в CSV недостаточно: потеряется информация из nodes, в том числе изолированные узлы и граница выгрузки. Не менять лимит 1 500 без проверки производительности и UI на полном наборе.

Практичное распределение после выбора React: участник 1 — только `alternatives/moneygraph-ai/frontend/`; участник 2 — адаптер API к корневой аналитике и проверка контракта; участник 3 — интеграция, тест полного набора и защита. Корневой Streamlit остаётся проверяемым резервным сценарием до готовности интеграции.

Финальная проверка: pipeline на исходных данных → три валидных CSV → открытие первого кандидата → связи и численные основания → узел без рёбер → предупреждение о четвёртом колене → запуск по README.
