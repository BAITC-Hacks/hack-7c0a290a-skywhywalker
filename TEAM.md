# Работа команды

Основной продукт — единое приложение React/FastAPI из корня репозитория. Командный main дал контракт кейса и правила ролей; MoneyGraph experiment — интерактивный интерфейс, аномалии и AI-функции; design — идеи компактного рабочего пространства. Подробнее: [сравнение MVP](docs/MVP_COMPARISON.md).

## Разделение работы на троих

Перед началом блока договоритесь о владельцах файлов. Пример распределения; конкретные имена назначает команда:

| Участник | Основная зона | Результат |
|---|---|---|
| Интерфейс | `frontend/src/**` | Один основной сайт, понятный сценарий и браузерная проверка |
| Аналитика и API | `backend/**`, `pipeline.py`, профильные тесты | Контракт данных, расчёты и ограниченные read-only инструменты агента |
| Проверка и защита | README, `docs/**`, сценарии приёмки | Проверка на официальных файлах, сопоставление с ТЗ, воспроизводимый показ |

Один участник выполняет роль интегратора: последовательно объединяет изменения, запускает общие проверки и объявляет версию для защиты. Не начинайте второй независимый сайт, пока есть незавершённый основной сценарий.

## Как не конфликтовать в Git

- Изменения готовятся в отдельных ветках и проверяются через pull request.
- Ветка защищает историю, но не устраняет конфликт одновременных правок одного файла. Владельцы пересекающихся файлов сначала договариваются; новую задачу проще отделить компонентом или модулем.
- До начала изменения получите актуальный `main` и создайте свою ветку. Перед слиянием согласуйте с интегратором порядок обновления; не переписывайте чужую ветку и не используйте force-push в общую историю.
- Изменения API, шести ролей или трёх CSV сопровождаются тестами и документацией.
- Перед объединением: `python -m pytest tests -q` и `pnpm build` из `frontend`. Изменения интерфейса проверяются в браузере.
- Официальные Parquet остаются локально в `data/official`. Не добавляйте в Git исходные данные кейса, `.env`, ключи, виртуальные окружения и `node_modules`.
- GID передаются строками. Изоляты, seed, границы четвёртого перехода и дневная точность сохраняются при любых преобразованиях.
- Результаты обновляются в [VERIFICATION.md](VERIFICATION.md). Прежняя проверка отдельной ветки не считается проверкой интеграции.
- Перед защитой остановите добавление функций, пересоберите frontend и пройдите [пятиминутный сценарий](docs/DEMO.md). В выступлении один человек объясняет проблему, второй демонстрирует продукт, третий готовит резерв CLI и отвечает за воспроизводимость.
