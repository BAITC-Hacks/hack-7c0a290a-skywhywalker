# MoneyMap — HackAlem AI

MoneyMap — веб-инструмент для AML-аналитика в кейсе Freedom «Граф денег». В начале расследования известен 81 клиент из нижнего уровня цепочки. Данные переводов содержат уже 2 248 клиентов, и аналитику нужно понять, кто собирает, передаёт и распределяет средства. MoneyMap строит направленный граф, объяснимо назначает узлам роли и выдаёт очередь клиентов для углублённой проверки.

Результат для аналитика: **ввести любой `gid` → увидеть его место в сети, направление и суммы переводов, гипотезу роли и численное обоснование приоритета**. Решение помогает определить, кого изучить первым; окончательное заключение остаётся за человеком.

## Что реализовано

- Воспроизводимый расчёт из трёх исходных `.parquet` в `nodes_roles.csv`, `clusters.csv`, `top_nodes.csv`.
- Роль, `role_score`, `priority_score`, кластер и короткое численное `evidence` для каждого из 2 248 узлов.
- Рейтинг 50 ранее неизвестных узлов для первой проверки.
- Веб-интерфейс: обзор задачи, очередь проверки, поиск по произвольному `gid`, граф со стрелками, карточка узла, список переводов, кластеры и методика.
- Опциональная AI-справка по выбранному узлу на основе рассчитанных фактов.

## Сценарий работы

```text
3 файла parquet → проверка данных → направленный граф → роли и приоритеты
                                                   ↓
                            3 CSV + веб-экран расследования
```

На стартовом экране уже показан первый кандидат: фрагмент его графа, приоритет и три численных основания. Кнопка «Открыть расследование» ведёт к переводам и карточке узла. В «Приоритетах» доступна полная очередь, а ввод произвольного `gid` работает по тому же сценарию. Прямые связи расположены слева направо: плательщики → выбранный узел → получатели. Плотность карты переключается от 9 до 65 узлов; интерфейс всегда обозначает, что это фрагмент, а не вся сеть.

Визуальный референс: [макет](design/reference.png). Это AI-сгенерированный концепт, не скриншот продукта: придуманные генератором имена и числа не используются в приложении. [Запрос и решения по дизайну](design/PROMPT.md). Стили вынесены в `ui.css`.

## Технологии и архитектура

Python, pandas и PyArrow читают выгрузку; NetworkX считает графовые признаки, кластеры Louvain и пути от исходных узлов; NumPy и SciPy используются при расчётах. `pipeline.py` полностью формирует CSV и проверяет их схему. Streamlit в `app.py` показывает результаты, Plotly рисует локальный направленный граф. Опциональная текстовая справка вызывается через OpenAI Responses API (`gpt-6-luna` по умолчанию); роль и рейтинг рассчитываются локально и воспроизводятся без API.

## Данные

Положите выданные организаторами `nodes.parquet`, `edges.parquet` и `transactions.parquet` в папку `data/`. Сырые данные не хранятся в Git. Внешние источники данных не используются. Структура:

```text
MoneyMap/
├── data/
│   ├── nodes.parquet
│   ├── edges.parquet
│   └── transactions.parquet
├── pipeline.py
├── app.py

```

## Запуск

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python pipeline.py --data data --out out
streamlit run app.py
```

Откройте адрес, который напечатает Streamlit (обычно `http://localhost:8501`). Если CSV ещё нет, приложение рассчитает их при первом запуске. Для проверки жюри достаточно одной команды после установки зависимостей:

```bash
python pipeline.py --data data --out out
```

Результат: `out/nodes_roles.csv`, `out/clusters.csv`, `out/top_nodes.csv`. Пайплайн проверяет, что рёбра согласованы с транзакциями, а все роли и обязательные поля заполнены. На предоставленных данных полный расчёт занимает около секунды на машине разработки.

Проверка интерфейса без браузера и без API-вызовов (нужны исходные данные в `data/`):

```bash
python -m unittest discover -s tests -v
```

Тесты проходят разделы, переходы к кандидатам, плотность и радиус графа, узел без связей и предупреждение об обрезанной глубине. Они проверяют поведение Streamlit, но не заменяют визуальную проверку в браузере.

Распределение работы и правила слияния для команды: [TEAM.md](TEAM.md). Интерфейс из этой ветки не нужно автоматически объединять с другим MVP: сначала назначьте один основной сайт и его владельца.

Опциональную AI-справку можно включить, введя ключ в поле приложения либо задав `OPENAI_API_KEY` перед запуском. По умолчанию используется `gpt-6-luna`; модель можно заменить через `OPENAI_MODEL`. API получает только численные факты выбранного обезличенного узла и его восемь крупнейших наблюдаемых связей. Ключ не записывается в CSV и не должен попадать в Git.

## Как работает модель

| Роль | Основное правило |
|---|---|
| `coordinator` | ≥2 входа, ≥2 выхода, связь минимум с двумя seed, посредничество выше 92-го процентиля ненулевых значений |
| `consolidator` | не seed; ≥3 плательщика; входящий объём выше медианы; удержание ≥35% внутри выгрузки |
| `distributor` | ≥5 получателей, относительно мало входящих источников |
| `transit` | не seed; есть вход и выход; `out_kzt / in_kzt` от 0.65 до 1.5 |
| `terminal` | нет исходящих, есть входящие, узел найден раньше четвёртого колена |
| `peripheral` | другие узлы, включая листья четвёртого колена и seed без исходящих |

Правила применяются сверху вниз; все пороги и формулы находятся в `pipeline.py`. `role_score` отражает силу совпадения с правилом, а не вероятность правонарушения. В `evidence` есть численные основания; длина ограничена 200 символами.

Приоритет = 25% центральность + 22% оборот + 20% число seed, из которых достижим узел + 18% число связей + 15% сигнал роли. Уже известные seed и обрезанные листья получают понижающий коэффициент. В `top_nodes.csv` входят 50 ранее неизвестных узлов. Кластеры построены методом Louvain на неориентированной проекции; направление переводов сохраняется для ролей, путей и экрана расследования.

## Быстрая проверка на защите

1. Запустите пайплайн и покажите три CSV.
2. На экране «Обзор» покажите задачу и первые три кандидата.
3. Откройте одного кандидата кнопкой или через «Приоритеты»: покажите роль, суммы, стрелки и путь от seed.
4. Введите произвольный `gid` жюри и объясните решение по `evidence` и рёбрам.

## Потенциал следующей версии

Переход от разовой выгрузки к регулярному обновлению графа; сохранение решений аналитика и обратной связи по ложным срабатываниям; подключение разрешённых дополнительных банковских данных для подтверждения транзита и остатков; сравнение графа по периодам. Эти возможности не входят в текущий прототип.

## Границы интерпретации

Граф содержит только исходящие внутрибанковские переводы от seed, четыре колена, июль 2026 и операции от 5 000 ₸. У seed входящие из-за границ выборки неизвестны. Листья четвёртого колена не классифицируются как конечные получатели. «Удержание» — разница входа и выхода внутри наблюдаемого графа, а быстрый выход в течение двух дней — временный признак, не доказательство идентичности средств.

Выводы системы — гипотезы для AML-проверки, а не утверждения о виновности клиентов.

Развёрнутой публичной версии пока нет. Прототип запускается локально указанными выше командами.
